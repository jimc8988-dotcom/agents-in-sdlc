VS Code のエージェントモードでは、Copilot がコードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。作業は自分のマシンでリアルタイムに行われます。Copilot Chat ではツールの呼び出しやファイル編集を確認し、差分をインラインでレビューして、変更を個別に採用または取り消せます。エディターを離れずに追加のプロンプトを送り、作業を調整したり拡張したりできます。

このレッスンでは、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 作業中のセッションにライトモードの切り替えを追加するよう依頼します。

## シナリオ

[レッスン 4][previous-lesson] で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも必要です。新しい会話を始めるのではなく、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューでは、エージェントが調べたファイル、実行したコマンド、提案した編集などの手順を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作を含めてチャットに表示されます。

1. レッスン 4 で使った Copilot Chat ビューに戻ります。
2. エージェントのツール呼び出しを確認できるようチャットをスクロールします。ファイルの読み取り、編集、実行を求められたターミナルコマンドが表示されます。
3. ファイル編集が提案されると、差分がインラインで表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消して再度試すには **Undo** を選択します。
4. チャット上部の **Files changed** 表示を開くと、セッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは **Allow** を表示して一時停止します。実行してもよいコマンドのみ許可してください。

5. エージェントがハイコントラストモードを実装するまで待ちます。最後に変更内容の要約が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。会話を続けることで、エージェントは変更したコンポーネント、スタイル、ローカルストレージの使い方などのコンテキストを保ちます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの変更を提案します。
3. ハイコントラストモードと同じように、新しい編集を確認して、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが期待と異なる方針に進んだ場合 (たとえばトグル UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の **Stop** ボタンで停止し、補足のプロンプトを送信します。

> [!TIP]
> 作業中のセッションに指示を追加すると、最初からやり直すより速く調整できます。たとえば、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを統合する」、「両方の切り替えにキーボードショートカットを追加する」と依頼できます。

## 変更されたファイルをレビューする

コミットの前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. いくつかのファイルを開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保存など、カスタムエージェントが示したアクセシビリティの手法が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視し、各ファイル編集をレビューして、変更を採用または取り消し、会話のコンテキストを保ったまま追加の作業を依頼しました。

このレッスンでは、作業をリアルタイムで監視し、個々のファイル編集を採用または取り消し、追加プロンプトでセッションを案内する方法を確認しました。
